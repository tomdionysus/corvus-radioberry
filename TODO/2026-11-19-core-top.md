# Stage 7: the core's own top, from first principles

Done: built, checked and released in 0.7.0 (2026-11-20). Kept as the
design record.

The board owner's direction (2026-11-19): leave behind what is
specifically Hermes-Lite 2 and design the core's top from first
principles. This note is the design; his decisions are at the end.

## What is still Hermes-Lite 2

After stages 1 to 6 every block is this project's; what remains is
`radio.sv`'s own logic and the interface it imposes:

- **The command interface.** The images' radio space takes Hermes-Lite 2
  Protocol 1 commands (address 0x00 to 0x3f, 32 bits) passed through
  from the driver's `radioberry_command`; `radio.sv` decodes them.
- **The frequency calculation** in the FPGA (stage 4).
- **Behaviours a Hermes-Lite 2 client expects**: receiver 0 following the
  TX frequency when not in duplex with one receiver; PureSignal (the DAC
  words into receiver 1 while transmitting); TX predistortion (not built;
  needs the old CORDIC); CW keyed through the TX samples' low bits (CWX:
  the images never pass those bits to the core); the TX buffer's
  "tape recorder" sample accounting.
- **The TX state machine's shape**: PRETX latency in quarter
  milliseconds, PTT hang, CW hang, all from Hermes-Lite 2 registers 0x10
  and 0x17.

## Proposal

1. **The gateware gets its own register map** in board space for
   everything the radio does: receiver count and rate, each receiver's
   and the transmitter's phase word (stage 4: the driver computes it),
   LNA gain, drive, PA enable and T/R disable, PTT hang and TX start
   latency, CW hang. Radio space goes.
2. **The driver translates.** It already turns each `radioberry_command`
   into frames; it maps the Hermes-Lite 2 address and data to the new
   registers, computes the phase words, and applies the client-visible
   rules (receiver 0 follows TX when not duplex with one receiver). The
   ABI, the daemon, the SoapySDR module and the tools do not change;
   their tests keep passing as they are. The translation is pure logic
   in `rb_frame.h`/`rb_logic.h`, unit-tested in userspace like the rest.
   (The alternative, a new ABI with the daemon translating, touches every
   component; not proposed.)
3. **Dropped**: PureSignal, predistortion and `cpl_cordic.v`, CWX, the
   "tape recorder" accounting. Kept, as this project's design: software
   PTT and jack keying under the permission bit, the raised-cosine CW
   envelope, PTT hang, a TX start latency that lets the FIFO fill.
4. **One release with stage 4**: the driver and the images ship
   together; an older driver refuses the new images by their CAPS
   version (as it does a wrong board's).
5. **Checked at the client level**, since the interface changes: a
   testbench drives the stage 6d core with Hermes-Lite 2 commands and the
   new core with what the driver's translation produces from the same
   commands (the translation compiled from the driver's header through a
   small C++ generator of the register writes, or the same table written
   in the testbench and checked against the driver's unit tests), and
   compares the receive words and the DAC words, every output on every
   clock, PureSignal off. Then the usual gates; keyed runs only for the
   TX start and hang (software PTT, on the board owner's go-ahead).

## Decided (board owner, 2026-11-19)

1. The translation is in the driver; the ABI, the daemon, the SoapySDR
   module and the tools do not change.
2. Dropped: PureSignal, predistortion (with `cpl_cordic.v`), CWX, the
   tape-recorder accounting.
3. Stages 7 and 4 together, in one release with the driver.
